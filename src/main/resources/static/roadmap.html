Scope A: Extraction Hardening

  • 1Table-aware PDF extraction — Tabula-java for financial tables, preserving column structure
  • 2Dual-year extraction — current + prior year in single pass, YoY validation checks
  • 3Retry with self-correction — if validation fails, retry with corrective prompt
  • 4Computed confidence — objective score from completeness + validation, replaces LLM self-report
  • 5Cash flow statement — 5 new fields, cash flow identity check, free cash flow
  • 6EDGAR cache + regex fix — 24h cache for 5MB tickers file, safe JSON parser

Scope B: Knowledge Architecture

  • 1Company master table — canonical names, ticker, CIK, sector. Companies as first-class entities.
  • 2Knowledge compilation — LLM synthesizes raw chunks into structured summary articles per section
  • 3Health dashboard — extraction rates, field coverage, anomaly detection, contradictions. Zero LLM cost.
  • 4Entity relationships + CSV — subsidiary/competitor/supplier links, spreadsheet export

A2
Dual-Year Extraction High Impact, Low Effort
Financial statements always show current + prior year. Currently we extract only current year and throw away the comparative. Free data at zero extra LLM cost — same pages, same prompt, just ask for both years.

Scope B Knowledge Architecture — 4 Phases
Inspired by Karpathy's LLM Knowledge Bases. Transform FinLens from document extraction into a financial knowledge base.
B1
Company Master & Temporal Modeling Foundation
Normalize company identity. Drop the 1:1 unique constraint. Enable multi-period tracking.
BEFORE
financial_data.company_name = "Micron Technology, Inc." (just a string, no normalization) document_id: UNIQUE constraint → 1 extraction per document → can't track Micron across FY2022, FY2023, FY2024
AFTER
company table: canonical_name: "micron technology" ticker: "MU", cik: "0000723125" sector: "Semiconductors" financial_data.company_id → company(id) financial_data.period_type = FY | Q1 | Q2 | Q3 | Q4 → trend queries, YoY analysis, peer groups
